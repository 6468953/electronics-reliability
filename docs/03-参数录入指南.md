# 参数录入指南（把示例值换成标准真值）

> 目标读者：愿意花 1~2 天把参数库做准的人
> 前置阅读：[`02-使用边界与限制说明.md`](02-使用边界与限制说明.md) §2.1

---

## 一、为什么必须做这一步

系统里所有失效率都从 `backend/params/*.json` 读。这些数字目前是**公开文献的典型量级**，不是标准原表的值。这意味着：

- MTBF 的绝对值不能对外引用
- 但同一套参数下的**相对比较**（A 方案比 B 方案好多少、哪个器件是短板）仍然可信

把表录进去之后，第一条限制才消失。这是提升可信度里**性价比最高**的一步——比补 Method II/III、比换数据库都便宜。

## 二、两套标准的获取难度完全不同

| 标准 | 拿得到吗 | 工作量 |
|---|---|---|
| **MIL-HDBK-217F Notice 2** | 免费公开。`quicksearch.dla.mil` 搜 `MIL-HDBK-217F`，下 `Revision F` + `Change Notice 1` + `Change Notice 2` 三份 PDF 拼合 | 约 1~2 人日 |
| **Telcordia SR-332 Issue 4** | 要买。Ericsson 按 Enterprise License 销售，官网只受理报价申请，正文禁止转发 | 先采购，再录 |
| GJB/Z 299C、GJB/Z 35-93 | 国内标准发行渠道购买 | 同上 |

**建议先做 MIL-217F**：零成本，且能覆盖大部分客户要求。

## 三、四步流程

```bash
# 1. 导出待填工单（生成 docs/参数录入工单_MIL-217F.xlsx）
backend/.venv/Scripts/python.exe tools/param_worksheet.py export --standard MIL-217F

# 2. 用 Excel 打开，只在浅黄色的「录入值」列填数
#    留空 = 不动，系统继续用当前值

# 3. 先校验，不写文件
backend/.venv/Scripts/python.exe tools/param_worksheet.py import --standard MIL-217F --file docs/参数录入工单_MIL-217F.xlsx

# 4. 校验通过后写回
backend/.venv/Scripts/python.exe tools/param_worksheet.py import --standard MIL-217F --file docs/参数录入工单_MIL-217F.xlsx --apply
```

工单四张表：

| 工作表 | 内容 | 对应标准位置 |
|---|---|---|
| `1-λ基础失效率` | 35 个类目的 λ_b | 附录 A（零件计数法）各类别表 |
| `2-环境因子（π_E）` | 9 个环境档的倍率 | 环境因子表 |
| `3-质量因子（π_Q）` | 4 个质量档 | 质量因子表 |
| `4-温度因子（π_T）` | 各类目的参考温度、幂指数或活化能 | 各类别章节的温度模型 |

「标准章节」列给的是**章节名称**而不是编号——编号在不同 Notice 之间会挪，写错反而误导，按名称在 PDF 里找更稳。

## 四、填表时最容易出错的四件事

1. **单位**。工单要的是 **FIT**（每 10⁹ 小时）。标准原文若给的是 `failures/10⁶ h`，要 **×1000**。差这一千倍，MTBF 就差三个数量级。
2. **别四舍五入**。原表给 0.0023 就填 0.0023，不要填 0.002。工具会校验量级，但判断不了你抹掉了有效位。
3. **别抄错行**。这是最常见的错误，工具只能通过单调性粗查（π_E 应随环境恶劣递增、π_Q 应按质量递减）发现一部分。**建议两个人各填一份交叉核对**——这一步没有捷径。
4. **温度模型分两种**：
   - 幂律（`power_law`）：填 `幂指数 n` 与参考温度
   - Arrhenius（`arrhenius`）：填 `活化能 Ea (eV)` 与参考温度
   表格里的「公式形式」列已经写明该类目用哪种，别把 n 填进 Ea 里。

## 五、工具能校验什么、不能校验什么

| 能查 | 不能查 |
|---|---|
| 数值能否解析、是否 > 0 | 是否抄错行（除单调性粗查） |
| 是否超出量级（>1e6 或 <1e-6 FIT 会报错，通常是单位错） | 是否抄错列（比如把 π_S 填进了 π_Q） |
| π_E / π_Q 是否单调 | 是否漏了某个类目（留空就是"不填"） |
| 参考温度是否物理合理 | 标准版本是否对（Issue 3 的表填进 Issue 4 的库） |

**留空的格子不算错**，但覆盖率不到 100%，数据成色就停在 `partial`。

## 六、回写后会发生什么

| 变化 | 说明 |
|---|---|
| `xxx.json.bak` | 原文件自动备份，想回退直接覆盖回去 |
| `data_quality` 自动升级 | 全填 → `verified`；填了一部分 → `partial`；一个没填 → 不动 |
| 界面徽标变化 | 参数库页与结果页的「数据成色」标签同步变色 |
| 报告附录 C | 第一条从「示例量级」变成「已按标准原表录入」 |
| **历史报告不变** | 评估结果存的是快照（`result_json` + `param_version`），改参数只影响之后新跑的评估 |

## 七、录完怎么验证做得对

1. **重算一次演示项目**，对比录表前后的 MTBF。变化幅度通常在 2 倍以内——如果差了一个数量级，大概率是单位错了。
2. **看结果页顶部的「读数字前先看」**，第一条应该变成绿色的「已按标准原表录入」。
3. **抽查两个类目**：挑铝电解电容和 MCU，翻到标准原表对应格，确认 JSON 里的值与纸面一致。这一步别省，机器校验替代不了人眼。
4. **导出一次 PDF**，翻到附录 B 确认「数据质量」行，再翻附录 C 确认口径已更新。

## 八、如果标准买不到

法律上不能拿网上流传的 PDF 做公司用途——SR-332 正文首页有 Enterprise License 声明。可选的三条路：

1. **只报 MIL-217F**。很多客户接受，且这份免费。
2. **走采购**。SR-332 需询价，问清是单用户还是企业授权，以及是否绑定 ARPP 软件。
3. **用计数型现场数据替代**：Quanterion 的 NPRD（非电子件）/ EPRD（电子件）订阅约 $800/用户/年，卖的是实测失效率而非标准授权，可以同时解决机械件那个「占位值」问题。
